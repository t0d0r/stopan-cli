# 2026-10-28 - profiles

## Done

- Profiles: the config file holds named profiles (server, token, and
  the user of the last login) and the current one (specs/auth.md
  "Profiles"). The v0.1.0 file is read as the profile `default` and
  saved in the new form at the next save.
- Choice of profile: `-P/--profile NAME` on every command and before
  the command, then STOPAN_PROFILE, the current one, the only one,
  `default`; STOPAN_URL / STOPAN_TOKEN still override.
- `login -P NAME` saves that profile and makes it current; `profiles`
  lists them with `*` on the one in use; `use NAME` switches;
  `logout` removes the token of the chosen profile, `--forget` the
  whole profile.
- The dashboard header shows the profile (`stopan [dev]`).
- Tests: internal/config (choice order, overrides, old file, remove,
  names, modes); cli_test TestProfiles with two fake servers; TUI header.
- Checked with the real config of v0.1.0 format: read as `default`, the
  file is left as is until the next save.

## Decisions

- One config file for all profiles (one place, one 0600 file).
- login makes its profile current; `use` switches back.
